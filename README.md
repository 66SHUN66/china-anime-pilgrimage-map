# 次元坐标 · 中国动漫巡礼地图

把国漫、动画电影、动画剧集、WEB 动画、漫画与特摄里**真实出现过的中国地点、建筑原型和剧情地**，做成一张可点击、可筛选、可核对来源的巡礼地图。

不是“动漫截图合集”，也不是“泛景点推荐”。每个点尽量做到：

- 左边是作品里对应场景的截图；
- 右边是同一建筑 / 街道 / 地名的实景；
- 详情卡底部写清来源，标“同机位 / 同建筑 / 同街区 / 原型 / 官方对照 / 待核”；
- 找不到同一场景就保留旧图并明确标“待核”，不用泛图硬凑。

## 数据口径

收录：

- 动画/漫画/特摄影片里出现过的真实中国地点；
- 有明确建筑原型的场景；
- 官方或媒体做过“动画 vs 实景”对照的地点；
- 只作为故事发生地、但作品明确写实地名的剧情地。

不收录：

- 主题乐园、公司总部、创作中心、快闪店、联名活动；
- 纯架空作品硬编出来的坐标；
- 没有作品内证据、只靠“看起来像”的地点；
- 把动画场景说成实拍、或把泛景点说成同一机位的条目。

### `imageMatch` 取值

| 值 | 含义 |
|---|---|
| `同机位` | 机位、建筑、构图能对上 |
| `同建筑` | 同一栋建筑，机位可能不同 |
| `同街区` | 同一街区/公园/桥段，无法确认同一机位 |
| `原型` | 明确的原型建筑，但作品做了改编 |
| `官方对照` | 官方或权威媒体发布的对比图 |
| `待核` | 尚未找到同一场景证据，详情页会标“待核 · 泛图” |
| 空 | 早期未标点，仍需逐点核 |

> `待核` 不是“已确认”，只是保留候选。欢迎按 `CONTRIBUTING.md` 提供证据替换。

## 数据字段

`data/works.json` 顶层是作品数组，每个作品包含：

```json
{
  "id": "work-id",
  "title": "作品名",
  "year": 2020,
  "form": "animation",
  "typeName": "动画电影",
  "region": "地区",
  "source": "作品来源",
  "spots": []
}
```

每个 spot 的关键字段：

```json
{
  "id": "spot-id",
  "name": "地点名",
  "city": "城市",
  "province": "省",
  "lat": 00.0,
  "lng": 000.0,
  "basis": "实拍地 / 剧情地 / 建筑原型",
  "still": "作品截图 URL",
  "real": "实景图 URL",
  "imageMatch": "同机位",
  "stillSrc": "截图来源",
  "realSrc": "实景来源",
  "pairNote": "对照说明"
}
```

坐标是地点中心点，不是拍摄机位；剧情地只代表故事发生地。

## 版权与图片

**本仓库不打包剧照和实景图。** 页面中的图片全部以远程 URL 引用，版权归原作者与来源网站所有；仓库只保存 URL、来源链接和对照说明。

- 保留水印，仅作个人非商业巡礼参考；
- 每张详情卡底部都有来源入口；
- 如你是版权方并要求删除，请开 Issue 或联系仓库维护者，会尽快移除对应 URL 与条目；
- 详见 [`sources.md`](sources.md)。

## 贡献

欢迎补点、纠错、替换“待核”图。一个可合并的补点至少需要：

1. 作品名 + 集数/时间码；
2. 片中截图；
3. 同一建筑/街道的实景图；
4. 两边来源链接；
5. 一句对照说明，写清是“同机位 / 同建筑 / 同街区 / 原型”。

具体见 [`CONTRIBUTING.md`](CONTRIBUTING.md)。

## 已知限制

- 远程图片可能因百度/anitabi CDN 防盗链、限速或失效而加载失败，详情页会显示“图源失效 · 待补”；
- 部分早期条目仍是泛图，已标 `待核`；
- 坐标精度到地点中心，未逐点做门牌级校正；
- 作品数量与地点数量会继续增长，README 统计以 `index.html` 的计数条为准。
